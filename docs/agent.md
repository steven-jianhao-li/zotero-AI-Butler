# Agent 研究助手

主窗口的 **Agent** 标签位于「AI 总结」和「任务队列」之间。左侧管理会话，中间通过「对话 / 轨迹」切换研究回答和完整执行记录。点击右上角「计划与团队」查看研究计划、团队成员和上下文用量。窄窗口下，会话列表收进左上角的侧栏按钮。

## 开始研究

1. 在 API 设置中配置支持原生工具调用的模型端点。
2. 新建 Agent 会话，在输入框右下方选择主控模型；默认沿用现有 API 路由，并在一次运行内固定端点。输入框下方的选项按钮可设置精读模型、PDF 输入方式和运行预算。
3. 如需限定起点，在 Zotero 中选中文献，点击输入框左下方的「+」按钮。Agent 的检索范围为这些条目所在的文献库；选中条目不是整个检索范围的限制。
4. 输入研究目标，例如「比较库中关于检索增强生成的实验结论，先读已有笔记，必要时核对原文，并指出证据不足之处」。

Agent 会先检索条目和笔记预览，再按需分页阅读笔记，最后对需要核实的论文调用原文精读。回答区支持 Markdown、表格和可点击的 Zotero 引用。AI 笔记属于二手证据；模型应将其与原文核验结果区分。

独立研究问题可以分给多个只读成员并行处理。「计划与团队」面板显示每个成员的任务、状态和结果，主 Agent 汇总最终回答。当前团队为协调者和一层研究成员，每次运行最多六名成员，一次最多并行分派三名。

## PDF 与 Base64 精读

精读模型可以与协调模型分开选择。协调器适合擅长工具调用的模型，精读器可以选择支持原生 PDF 输入的模型。

- **跟随 API 设置**：遵循精读端点或全局 PDF 设置。
- **Base64 PDF**：通过既有 `LLMService` 将原始 PDF 作为文件内容发送给精读模型，主对话只接收证据报告。
- **文本**：使用现有文本提取流程。
- **MinerU**：沿用 OCR 提取能力；Agent 请求不自动创建 OCR 附件、笔记或外部 Markdown 副本。

Base64 请求失败会报告错误，不会静默切换为文本。是否支持 PDF 取决于实际模型和 API 网关。主 Agent 的历史及证据存储不包含 Base64 文件字节。

## 权限

| 模式         | 行为                                               |
| ------------ | -------------------------------------------------- |
| 只读（默认） | 检索、阅读、精读、规划和团队研究，不修改文献库     |
| 逐次确认     | 展示具体工具和参数，点击允许后执行该次修改         |
| 允许整理     | 可创建笔记、创建分类、添加或移除分类成员、调整标签 |

修改工具会核验条目所属库及库的可编辑性，并记录修改前后的状态。子 Agent 始终只读。当前不提供删除文献、删除附件、执行脚本或任意文件访问工具。

已成功执行或执行结果不确定的相同修改不会自动重放。若需要重复创建完全相同的对象，应先核对当前库状态，再新建会话明确提出要求。重启插件后，恢复的会话重新使用只读权限。

## 长会话与停止

上下文预算默认 256K，单次输出默认 8192 token，可按模型规格调整，输出上限为 32768。预算包含系统提示、工具定义、历史和预留输出。接近上限时先缩短较早的工具输出，再总结历史，保留近期完整调用及证据引用；原始证据可按引用重新读取。

默认每次运行最多 32 步，所有成员共享 128 次工具调用预算。用量为估算及 API 返回的计数，精读和部分供应商未返回的用量可能未计入，不应作为账单统计。

「停止」会取消模型请求、待审批操作及后续工具执行。正在提交的数据库事务可能已经完成，会保留其结果；已启动的 Zotero 原生文件下载或索引需要等待自身结束。后续发送消息可继续研究。

会话存放在 Zotero 数据目录的 `ai-butler-agent` 文件夹，独立于任务队列，包含对话、证据及修改记录。API 密钥仍由现有 API 设置管理，不写入会话文件。删除会话只删除其本地历史，不撤销已经完成的文献库修改。
