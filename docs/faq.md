## 可以分析 EPUB 吗？旧版 Zotero 会受影响吗？

可以。在支持 EPUB 的 Zotero 7 或更新版本中，将未加密的 EPUB 附加到普通文献条目（例如图书）下，下载到本地，再选择该条目进行 AI 总结、精读或追问。自动扫描也会识别可用的 EPUB 附件。

插件复用 Zotero 的原生 EPUB 解析能力，按书籍阅读顺序提取正文，以文本方式发送给模型。PDF 的处理模式设置仅影响 PDF；同一条目有多种附件时，优先 PDF，其次 EPUB，最后网页快照。同类型有多个 EPUB 时使用最早添加的一个。

EPUB 能力按需检测和加载，同时兼容 Zotero 的旧版 JSM 与新版 ESM 接口。Zotero 6 或缺少可用 EPUB 接口的安装会跳过 EPUB 自动分析，手动分析时给出提示；PDF 和网页快照的分析仍可使用。

目前支持可提取正文的 EPUB，不对书中图片执行 OCR，也不解密受保护的电子书。EPUB 沿用现有文本输入长度限制（约 10 万字符），超长书籍尚不支持完整的分块处理。

## 快速追问保存后，如何在完整追问中继续？

在快速追问的回答下点击“保存”，然后打开该论文的“完整追问”。已保存的问题和回答会一起恢复，并用于后续提问的上下文。新保存的快速追问与完整追问共用该论文的 AI 精读笔记；旧版独立的“后续追问”笔记仍可读取。

快速追问中尚未保存的内容不会自动带入完整追问。完整追问是否自动保存回答由“保存追问记录”设置控制。

## 关闭自动滚动后，为什么笔记编辑仍可能跳出？

“自动滚动到最新输出”控制 AI 输出区和快速追问的滚动，保存设置后即时生效。开启时，向上滚动阅读历史内容会暂停跟随，回到底部后恢复。

笔记编辑时失去焦点是另一条刷新路径的问题。状态列现在只重绘相关文献行，不重建列表；侧栏自动重绘也会保留正在编辑的笔记与正在使用的快速追问。编辑侧栏笔记时，需先保存或取消才能手动刷新。切换论文或手动刷新快速追问前，请先保存需要保留的内容。

## 🔴 Gemini 429 报错 / 速率限制

### 问题描述

使用 Google Gemini API 时报错 `429`，提示超出速率限制或配额用尽。

### 原因分析

Google AI Studio 免费层级对 API 调用有配额限制，不同模型的限制不同。例如：

- 某些模型在免费层级下不可用（如曾经的 `gemini-2.5-pro`）
- 批量处理论文时容易超出每分钟请求限制

### 解决方案

**方案一：更换为免费层级支持的模型**

1. 访问 [AI Studio 用量页面](https://aistudio.google.com/usage)
2. 点击 **"速率限制"** → **"所有模型"**
3. 查看当前免费层级支持的模型（如 `gemini-2.0-flash`）
4. 在插件中修改模型名称为支持的模型

## 🔴 错误 20015: The parameter is invalid

### 问题描述

使用第三方平台（如硅基流动 SiliconFlow）时报错：

```
错误: 20015: The parameter is invalid. Please check again.
```

### 原因分析

部分第三方模型不支持多模态（Base64 编码的 PDF）输入。

### 解决方案

1. 打开 **AI 管家仪表盘** → **快捷设置**
2. 进入 **模型平台** 页面，展开报错模型的详情
3. 将该模型的 **PDF 处理方式** 切换为 **"文本提取"** 或 **"MinerU"**
4. 重新尝试分析论文

新版 AI 管家已将总结、思维导图、填表、文献综述和后续追问统一接入 LLM 输入中间件。每个模型都可以在 **模型平台** 页面单独覆盖 PDF 处理方式；如果仍选择 Base64，插件会按当前 Provider 的 Base64 请求结构发送 PDF，不会静默改成文本模式。

## 🔴 错误 20041: The model is not a VLM

### 问题描述

分析论文时报错：

```
错误: 20041: The model is not a VLM (Vision Language Model). Please use text-only prompts.
```

### 原因分析

您使用的模型不支持多模态输入（不能直接处理 PDF/图片），但插件当前配置为多模态模式。

### 解决方案

1. 打开 **AI 管家仪表盘** → **快捷设置**
2. 进入 **模型平台** 页面，展开该模型的详情
3. 将 **PDF 处理方式** 切换为 **"文本提取"** 或 **"MinerU"**
4. 重新尝试分析论文

如果您使用的是本地大模型或 OpenAI-compatible 接口，建议给对应模型长期设置文本提取模式；其他支持多模态的模型仍可继续使用 Base64。

## 🟡 AI 总结只有一句话 / 反应时间为 0

### 问题描述

分析完成后，笔记内容极少（只有一句话），且显示反应时间为 0。

### 原因分析

这通常是 API 调用失败的表现，可能原因包括：

- API 密钥配置错误
- 遇到了 429 速率限制
- 网络连接问题

### 解决方案

1. **检查模型平台**：确认密钥正确，在对应模型详情中点击 **"测试连接"** 验证
2. **检查是否触发速率限制**：参考上方 "429 报错" 解决方案
3. **查看任务详情**：在任务队列中点击失败任务的 **"详情"**，查看具体错误信息

## 🟡 论文无法再次被 AI 自动总结

### 问题描述

之前尝试分析某篇论文时失败（例如 API 密钥未配置或返回为空），之后该论文无法再次被自动分析。

### 原因分析

早期版本中，即使 API 调用失败或返回空内容，也可能会创建一个只有标题的"空笔记"。由于系统检测到已存在 AI 总结或 AI 精读，因此跳过了对应分析。

### 解决方案

**新版本已修复此问题：** 现在如果 AI 返回内容为空，系统不会创建空笔记。

**对于已存在的空笔记，可使用「清空空 AI 总结」或「清空空 AI 精读」功能批量清理：**

1. 打开 **AI 管家仪表盘** → **快捷设置** → **数据管理**
2. 点击 **"🧹 清空空 AI 总结"** 或 **"🧹 清空空 AI 精读"** 按钮
3. 确认后，系统将扫描库中所有论文，删除对应类型中只有标题没有实际内容的空笔记
4. 之后这些论文可以重新被 AI 分析

> 💡 **提示**：清理完成后会显示扫描论文数量和删除空笔记数量。
